# EDMW Mod Studio v1.4.0 Beta

**Status:** GitHub prerelease (beta) · **Updated:** 2026-11-07

This beta adds relay matchmaking, automatic relay sign-in when Mod Studio opens, and a 60-second authenticated heartbeat. The Friends dialog contains **Friends** and **Matchmaking** tabs. The Matchmaking panel keeps rooms and invitations in the list area, puts room controls in a right sidebar, and uses right-click or double-click to join a room.

The supported game's TCP/IP provider connects through a guarded, process-local x86 bridge. The relay handles sign-in, matchmaking rooms, and ICE offer/answer/candidate signaling. Game UDP and TCP traffic prefer direct WebRTC data channels negotiated with ICE and STUN. When direct ICE is unavailable, the authenticated WSS connection relays room-scoped UDP, TCP, and session-control frames. This fallback needs no inbound port forwarding; relay latency and bandwidth apply.

**Prepare game network** requires a connected matchmaking relay and usable local IPv4 mapping, assigns the room's virtual IPv4 mapping, and opens EDMW's normal game UI on each computer. The host starts the game through EDMW; other players use **Join by IP** with the displayed host address. Matchmaking does not transfer or install maps, so each player must already have the same map and supported game/provider build installed.

The game bridge selects a local IPv4 interface from ICE's selected or gathered candidates, then falls back to Windows' active default-route adapter; it does not use the public STUN-mapped address as a local adapter. It maps the adapter and matching route-table entries to each player's room address, and reports failures by player and setup stage. A hidden two-client loopback check covers virtual-address and route mapping, provider hooks, launch coordination, and bidirectional UDP, TCP, and control traffic through WSS. It does not exercise an actual in-game match or verify cross-internet gameplay.

The bridge forwards limited, multicast, and local subnet-directed discovery broadcasts over the direct peer channels to room members. In-game discovery should work even when the player hosting the game is not the player who created the Mod Studio matchmaking room.

The beta also hardens the provider hook for valid PE import tables without an original lookup table. Matchmaking now reports when the TCP/IP provider has not loaded yet, to distinguish that state from an active hook.

After **Launch EDMW**, Mod Studio restores and brings the game window to the foreground so the matchmaking dialog does not keep input. If Windows prevents activation, use **Alt+Tab** to select EDMW.

Matchmaking status reports connected ICE peers, whether the WSS fallback is ready or carrying traffic, relay frames queued and received, provider hookup, registered UDP sockets, packets sent (including room broadcasts), received packets, and packets delivered to the game. These counters help distinguish a game-provider issue from connection or local-delivery problems.

## Beta scope and compatibility

- The Windows application is self-contained and targets 64-bit Windows 10 or later. A compatible, separately installed x86 game is required for gameplay.
- The bridge checks the supported game and provider hashes before hooking. Other game builds or modified providers may not be supported.
- All players should use the same supported game/provider build and matching gameplay data.
- Direct internet gameplay prefers ICE/STUN peer connectivity. The WSS relay carries gameplay frames when a direct path is unavailable; it uses the configured relay and adds relay latency and bandwidth.
- A real two-PC cross-internet game has not yet been validated. The relay fallback is verified between two desktop clients on loopback, but the public internet path and actual game match still need a two-PC test.
- A successful relay room join confirms room membership; it does not by itself prove that the game provider connected correctly. Check the Friends status after launching the game.

See the [user guide](../user-guide.md) for setup and the [online sharing and Render setup](../online-sharing.md) for relay deployment. The previous stable release remains [v1.3.0](https://github.com/jfh24/EDMW-Mod-Studio/releases/tag/v1.3.0).
