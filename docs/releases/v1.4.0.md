# EDMW Mod Studio v1.4.0 Beta

**Status:** GitHub prerelease (beta) · **Date:** 2026-11-02

This beta adds relay matchmaking, automatic relay sign-in when Mod Studio opens, and a 60-second authenticated heartbeat. The Friends dialog contains **Friends** and **Matchmaking** tabs. All map collaboration controls live in the map script page panel, which lists online friends beside **Invite** buttons, incoming map invitations beside **Join** buttons, and clearly labeled **Host LAN session** and **Join LAN** controls.

The supported game's TCP/IP provider connects through a guarded, process-local x86 bridge. The relay handles sign-in, matchmaking rooms, and ICE offer/answer/candidate signaling. Game UDP and TCP traffic use direct WebRTC data channels negotiated with ICE and STUN; the relay carries no gameplay data. This release has no TURN server or gameplay relay fallback, so restrictive NAT or firewall settings can prevent a direct connection.

The bridge forwards limited, multicast, and local subnet-directed discovery broadcasts over the direct peer channels to room members. In-game discovery should work even when the player hosting the game is not the player who created the Mod Studio matchmaking room.

The beta also hardens the provider hook for valid PE import tables without an original lookup table. Matchmaking now reports when the TCP/IP provider has not loaded yet, to distinguish that state from an active hook.

After **Launch EDMW**, Mod Studio restores and brings the game window to the foreground so the matchmaking dialog does not keep input. If Windows prevents activation, use **Alt+Tab** to select EDMW.

Matchmaking status reports connected ICE peers, the provider hook, registered UDP sockets, direct packets sent (including room broadcasts), received packets, and packets delivered to the game. `TX` is sent traffic, `broadcast` is the broadcast subset, `RX` is traffic received over direct peer channels, and `game` is traffic handed to the local game socket. These counters help distinguish a game-provider issue from direct connection or local delivery.

## Beta scope and compatibility

- The Windows application is self-contained and targets 64-bit Windows 10 or later. A compatible, separately installed x86 game is required for gameplay.
- The bridge checks the supported game and provider hashes before hooking. Other game builds or modified providers may not be supported.
- All players should use the same supported game/provider build and matching gameplay data.
- Direct internet gameplay uses STUN for address discovery and requires peer-to-peer connectivity. There is no TURN server or gameplay relay fallback.
- Live cross-internet session validation has not been completed. Internet gameplay and direct connection behavior should be treated as beta and may need further fixes.
- A successful relay room join confirms room membership; it does not by itself prove that the game provider connected correctly. Check the Friends status after launching the game.

See the [user guide](../user-guide.md) for setup and the [online sharing and Render setup](../online-sharing.md) for relay deployment. The previous stable release remains [v1.3.0](https://github.com/jfh24/EDMW-Mod-Studio/releases/tag/v1.3.0).
