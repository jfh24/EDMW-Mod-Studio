# EDMW Mod Studio v1.2.1

Released 2026-10-15. This update expands custom effects and makes their authoring and target selection easier to use.

## Custom effect cards and target catalog

The effect editor groups its controls into compact cards for the trigger, outputs, and optional ability button. Its output catalog contains all 51 numeric stat choices, with units, ranges, and help for each. **Add output** combines several distinct changes under one trigger, duration, and button. Clicking the selected target's portrait opens a grouped, read-only stat overview with project overrides; unavailable values are marked **Not exposed**.

**Affected targets** opens a catalog of selectable unit and building cards. Search by name or object ID and filter by type, civilization, or age. Select several types for one proximity effect; checked items stay selected across searches, filters, and pages. **Use selected** updates the effect draft, while **Cancel** preserves its previous targets. Missing catalog references remain visible and must be repaired explicitly before applying. **Apply to project** commits the dialog as one undoable change, and saving the Mod Studio project retains its full target and output sets.

## Proximity and activated abilities

Proximity affects other eligible nearby units belonging to the same player. An emitter cannot satisfy its own aura condition; two sources of the same type can affect each other while nearby. A target loses the bonus when no eligible source remains in range. Multiple providers of the same effect do not multiply its outputs.

Activated abilities work for an individual source unit/building or eligible instances in the synchronized selected group. Timed groups start or restart together. A toggle turns an entirely active group off; a mixed group turns on together. Activated effects retain their source type as their only target type.

Custom ability records now use the intended native technology groups, and process hooks correct their age gate and civilization matching. Command handling distinguishes the game's network player identity from its internal player index. Placement reserves the native fixed-command and middle-action regions before choosing free cells, preserving commands such as Explore, Garrison, and Back to Work. Group buttons keep separate action identities without changing their native command definitions.

## Existing projects and installed packages

Legacy scalar target/output attachments and runtime formats remain readable. Multiple proximity targets expand into existing V5 runtime records with stable derived identities; reordering or repeating a target does not multiply an effect. A single target keeps its original identity. Duplicate identities and the combined 1,024-rule capacity are checked before installation.

Civilization exports continue to use reviewed portable packages, ownership checks, protected backups, and reversible uninstall. Uninstall with the game closed removes the selected package's effect rules and restores its owned values while retaining compatible independent edits. A launch with no runtime rules uses the normal game executable.

Older custom ability exports with records in the wrong technology group must be uninstalled, re-exported, and reinstalled. Disabling their runtime effects leaves installed button records in place and does not repair that table. Correctly grouped existing exports can use the updated process runtime on their next launch through Mod Studio. Runtime hooks do not modify the game executable or stock DLLs on disk.

## Compatibility and verification scope

The application and both installer templates carry version 1.2.1. The desktop executable remains self-contained for 64-bit Windows 10 or later; its effect runtime and map generator are x86 for the supported 32-bit game. A separately installed compatible game is required.

The regression checks for these changes are offline: project save/history, target normalization, package codec and tamper checks, fixture installation/sharing/launch aggregation/uninstall, managed-to-native rule parsing, native button metadata, group activation, proximity boundaries, and stat projection helpers. Fixture checks use disposable copies and verify that the source game files remain unchanged. Final target-picker behavior is reviewed from source; no new GUI, screenshot, or game launch is part of this release preparation.

Release preparation passed the native generator and effect test suites, both installer publishes, the desktop publish, and the core self-test. The runtime fixture suite passed all 51 outputs, multi-target persistence and capacity checks, seven managed-to-native payloads, button placement across 235 unit and 205 building contexts, and complete restoration of six original game files after uninstall. Embedded native and installer resources matched the built files by SHA-256.

These checks do not establish live correctness for every stat adapter, final visual acceptance, or multiplayer synchronization. Native game saves with active effects are unsupported because serialized overlays can be applied again after loading; activated state is session-only. Mod Studio project persistence is separate and retains authored settings. Launch experimental effects through Mod Studio and use matching installed gameplay data for multiplayer.
